## 2. 类继承与设计关系

```
Asic
 └── BM1370            (components/bm1397/bm1370.cpp / include/bm1370.h)
      └── BM1373       (components/bm1397/bm1373.cpp / include/bm1373.h)

NerdQaxePlus
 └── Q1370B            (main/boards/q1370.cpp / q1370.h)
      └── Q1373B       (main/boards/q1373.cpp / q1373.h)
```

- `BM1373 : public BM1370`：BM1373 复用 BM1370 的绝大部分逻辑，仅覆写 `getChipId()`、`getDefaultVrFrequency()`、`init()`、`getSmallCoreCount()`。
- `Q1373B : public Q1370B`：Q1373B 复用 Q1370B 的全部板级逻辑（电源/温度/风扇/CAN/初始化），仅在构造函数中改写型号字符串、ASIC 频率档位、默认频率/电压，并把 `m_asics` 替换为 `new BM1373()`。
- `BM1373` **未** 覆写 `jobToAsicId()` / `asicToJobId()`，直接继承 BM1370 的实现 —— 这是合理的，因为这两个 job/asic 映射逻辑与 BM1370 一致。

## 3. 完整性 / 可编译性逐项核查

### 3.1 源文件注册
- `components/bm1397/CMakeLists.txt` 的 `SRCS` 中已包含 `bm1373.cpp`。
- `main/CMakeLists.txt` 的 `SRCS` 中已包含 `boards/q1373.cpp`。

### 3.2 构建宏
- 根 `CMakeLists.txt`：`add_compile_definitions($ENV{BOARD})`，即环境变量 `BOARD=Q1373` 会定义宏 `Q1373`。
- `main/main.cpp` 中 `#ifdef Q1373 -> new Q1373B();` 完成板子实例化。
- `q1373.cpp` 中 `#ifdef Q1373 -> m_theme = new ThemeGeneric();` 主题初始化闭环。
- `main/displays/displayDriver.cpp` 中 `#elif defined(Q1370) || defined(Q1373)` 已处理显示分支。
- CI：`.github/workflows/build.yml` 与 `validate.yml` 的矩阵均含 `board: Q1373`。

### 3.3 被调用符号均可解析（均来自基类 `Asic` / `BM1370`）
`send6`、`send2`、`count_asics`、`setChipAddress`、`sendChainInactive`、
`setJobDifficultyMask`、`doFrequencyTransition`、`setVrFrequency`、`vrRegToFreq`、
`next_power_of_two`、`m_addressInterval`、`CMD_WRITE_ALL`、`CMD_WRITE_SINGLE`、
`ESP_LOGIE` 等均在 `components/bm1397/include/asic.h` 中声明/定义。

### 3.4 override 签名一致
`bm1373.h` 中 `getChipId()`、`getDefaultVrFrequency()`、`init(...)`、`getSmallCoreCount()`
的签名与 `bm1370.h` / `asic.h` 完全一致，可正确覆写。

### 3.5 潜在告警（非阻断）
- `BM1373_CORE_COUNT` 与宏 `REG_NONCE_TOTAL_CNT` 定义后未被使用。这与 `bm1370.cpp` 完全相同的写法一致，C++ 下文件作用域 `static const` 未使用默认不产生告警，不影响编译。

## 4. bm1373.cpp 与 bm1370.cpp 的逐处差异

下表是 `bm1373.cpp`（新）相对 `bm1370.cpp`（旧）的全部实质性差异：

| # | 位置 | bm1370.cpp | bm1373.cpp | 说明 / 风险 |
| --- | --- | --- | --- | --- |
| 1 | include | `#include "bm1370.h"` | `#include "bm1373.h"` | 头文件不同（bm1373.h 再 include bm1370.h） |
| 2 | TAG | `"bm1370Module"` | `"bm1373Module"` | 日志标签 |
| 3 | chip_id | `{0xaa,0x55,0x13,0x70,0x00,0x00}` | `{0xaa,0x55,0x13,0x72,0x00,0x00}` | **需硬件确认**：第 4 字节 `0x72`，并非直觉上的 `0x73`。该值用于 `count_asics()` 中与寄存器 0x00 返回值前 6 字节比对，必须与实际芯片返回的握手序列完全一致，否则探测不到芯片（`chip_counter=0`） |
| 4 | 核心数常量 | `BM1370_CORE_COUNT = 128`<br>`BM1370_SMALL_CORE_COUNT = 2040` | `BM1373_CORE_COUNT = 128 // TODO`<br>`BM1373_SMALL_CORE_COUNT = 7000 // TODO` | **需确认**：`SMALL_CORE_COUNT` 从 2040 改为 7000，且带 `// TODO`，直接影响 `getSmallCoreCount()` 返回值，进而影响算力/份额统计。`CORE_COUNT` 在两文件中均未实际被读取 |
| 5 | 构造函数 | `BM1370::BM1370() : Asic()` | `BM1373::BM1373() : BM1370()` | 父类不同，符合继承关系 |
| 6 | Misc Control (WRITE_ALL) | `send6(...,0x18,0xF0,0x00,0xC1,0x00)`（上方注释掉 `0xFF,0x0F` 版本） | `send6(...,0x18,0xFf,0x00,0xC1,0x00)` | **寄存器值差异**：高字节 `0xF0` → `0xFF`（`0xFf` 大小写不影响数值）。BM1373 打开了更多 Misc Control 位，需对照数据手册确认 |
| 7 | Core Register Control (WRITE_ALL) | 保留一行注释 `//...0x80,0x18` | 该注释行被删除 | 仅删注释，逻辑等价（仍是 `0x80,0x0C`） |
| 8 | set baud 注释块 | 含 `// set baud` + 注释掉的 `0x28` 指令 | 整段删除 | 仅删注释，无逻辑差异 |
| 9 | Misc Control (WRITE_SINGLE, per-chip) | `send6(...,0x18,0xF0,0x00,0xC1,0x00)` | `send6(...,0x18,0xFF,0x00,0xC1,0x00)` | 同 #6，单芯片版本同步改为 `0xFF` |
| 10 | Core Register Control (per-chip) | `...0x80,0x0C` | `...0x80,0x0c` | 仅大小写，数值等价 |
| 11 | jobToAsicId / asicToJobId | 在 bm1370.cpp 中**定义** | bm1373.cpp 中**不定义**（继承自 BM1370） | 行为一致 |
| 12 | getSmallCoreCount | 返回 `BM1370_SMALL_CORE_COUNT (2040)` | 返回 `BM1373_SMALL_CORE_COUNT (7000)` | 见 #4 |

### 关键差异归纳
- **真正影响行为的差异只有 3 处**：
  1. `chip_id` 第 4 字节 `0x70 → 0x72`（芯片探测握手）。
  2. `Misc Control` 高字节 `0xF0 → 0xFF`（WRITE_ALL 与 per-chip 两处同步）。
  3. `SMALL_CORE_COUNT 2040 → 7000`（算力/份额统计），且标注 `// TODO`。
- 其余差异均为命名、注释、十六进制大小写，属无害变化。

## 5. q1373.cpp 与 q1370.cpp 的差异

`Q1373B` 仅在构造函数中改写少量参数，其余板级方法（`initBoard`、温控、电源、CAN 等）完全继承自 `Q1370B`：

| 字段 | Q1370B | Q1373B |
| --- | --- | --- |
| `m_deviceModel` | `"Q1370"` | `"Q1373"` |
| `m_asicModel` | `"BM1370"` | `"BM1373"` |
| `m_asicCount` | 4 | 4 |
| `m_asicFrequencies` | `{500,515,525,550,575,590,600}` | `{300,325,350,375,400,425,450}` |
| `m_defaultAsicFrequency` | 600 | 350 |
| `m_defaultAsicVoltageMillis` | 1150 | 1050 |
| `m_asics` | `new BM1370()` | `new BM1373()` |

> 说明：`Q1373B` 未重设 `m_asicVoltages`、`m_absMaxAsicFrequency`、`m_initVoltageMillis`、
> PID、电流/电压上下限等，将沿用 `Q1370B` 的取值。若 BM1373 的电气特性与 BM1370 不同，
> 这些继承值（尤其是 `m_absMaxAsicFrequency = 1200`、`m_initVoltageMillis = 1200`）需要确认是否合理。

## 6. 建议跟进事项（不阻断编译，但影响实际运行）

1. 核对 `bm1373.cpp` 中 `chip_id` 的 `0x72` 是否为 BM1373 真实握手字节。
2. 落实 `BM1373_SMALL_CORE_COUNT = 7000` 的真实小核数量，移除 `// TODO`。
3. 核对 `Misc Control = 0xFF...` 寄存器配置是否符合 BM1373 数据手册。
4. 评估 `Q1373B` 是否需要覆写电压/频率上限与初始化电压等继承自 `Q1370B` 的参数。
